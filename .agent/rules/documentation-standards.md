# Documentation Standards

**Activation Mode**: Glob (`**/*.md`)

Apply these rules when working with Markdown documentation files.

## Documentation Principles

- Write clear, concise, and scannable documentation
- Focus on practical examples and use cases
- Keep documentation up-to-date with code changes
- Use consistent formatting and structure
- Make documentation accessible to developers of all skill levels

## Markdown Formatting

- Use proper heading hierarchy (H1 for title, H2 for sections)
- Include code blocks with language specification for syntax highlighting
- Use bullet points and numbered lists for better readability
- Add links to related documentation and external resources
- Include a table of contents for longer documents

## Code Examples

- Provide working, tested code examples
- Include both basic and advanced usage patterns
- Show error handling in examples
- Use realistic variable names and scenarios
- Comment complex or non-obvious code

## AI Project Documentation

- Document API endpoints and response formats
- Include example requests and responses for AI services
- Explain model selection criteria and trade-offs
- Document environment variables and configuration
- Provide troubleshooting guides for common issues

## API Documentation

- Document all public interfaces and methods
- Include parameter types, return values, and exceptions
- Provide usage examples for each major feature
- Document rate limits and usage quotas
- Explain authentication and authorization

## README Files

- Start with a clear project description and purpose
- Include installation and setup instructions
- Provide quick start guide with minimal example
- List prerequisites and dependencies
- Include links to detailed documentation

## Changelog and Versioning

- Maintain a CHANGELOG.md for notable changes
- Follow semantic versioning principles
- Document breaking changes clearly
- Include migration guides for major versions
- Tag releases with clear version numbers

## Diagrams and Visual Aids

- Use Mermaid diagrams for architecture and flows
- Include screenshots for UI features
- Create sequence diagrams for complex interactions
- Use ASCII art for simple visualizations when appropriate
